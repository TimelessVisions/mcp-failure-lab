# Benchmarks

This directory ships the **methodology** of a benchmark. It does not ship
comparative results about anyone else's software, and it never will from here.

That distinction is the whole design, so it is worth stating plainly:

- **Methodology, schema and vocabulary** — how a measurement is defined, what
  counts as applicable, what each outcome means, and how a run is planned and
  pinned. These are this project's own work. They are public.
- **Comparative results** — statements about how named third-party MCP
  implementations behaved relative to one another. These are produced only in a
  private development program, written to a git-ignored directory, and are not
  part of this distribution.

Publishing a league table of other people's software off the back of a narrow
scenario battery would be indefensible, and this project would deserve the
response it got.

## What is here

| | |
|---|---|
| Runner | [`run_benchmark.py`](run_benchmark.py) — the harness-latency benchmark, as code |
| Definition, schema and planning | `mcp-failure-lab benchmark --help` — generated from the models in `interop_lab.benchmark` |
| Vocabulary | Shared with the harness; see the classification list in [`../README.md`](../README.md#classification-vocabulary) |

Benchmark definitions and their schemas are **generated**, not committed here.
Regenerating one is a deliberate act that shows up as a diff:

```bash
uv run mcp-failure-lab benchmark plan      # write a definition
uv run mcp-failure-lab benchmark schema    # write its schema
uv run mcp-failure-lab benchmark plan --check   # the pin still describes the repo
```

A definition regenerated at the start of each run would agree with the run by
construction and could never detect that a target, a scenario or a build input
had moved.

The tracked tree must be clean when a benchmark runs: a benchmark measures a
commit, and a dirty tree means the results describe something the commit does
not.

## What is not here, and why

Comparative measurements of third-party implementations, the target definitions
they were produced against, and any result derived from either. None of it is in
this distribution, and none of it can be reconstructed from what is.

This is not a gap waiting to be filled by a later release. Findings and
comparative results about software this project did not write stay private
unless and until their maintainers have been through
[responsible disclosure](../docs/responsible-disclosure.md). That obligation
does not expire because a repository became public.

## Building your own

Nothing stops you constructing a private benchmark definition of your own: point
a definition at your own targets, run it, and keep the results wherever your own
disclosure policy says they belong. The methodology here is meant to be reused.
The results it produces about other people's software are yours to hold, on the
same terms.

## Rules the vocabulary keeps

These hold for any run, public or private, and they are the reason a number from
here can be read at all:

- **`NOT_APPLICABLE`, `NOT_MEASURED` and `INCONCLUSIVE` are three different
  things.** A scenario that does not apply to a target's negotiated revision is
  `NOT_APPLICABLE`. A dimension the run did not attempt is `NOT_MEASURED`. A
  result the evidence cannot decide is `INCONCLUSIVE`. None of the three is a
  failure, and none is a pass.
- **`applicable` is the denominator.** A rate is reported against what could
  have been measured, never against the full battery, and the denominator is
  carried alongside the number.
- **No overall ranking is produced, by design.** There is no best SDK here, no
  safest implementation, no most compliant target and no aggregate score. A
  narrow battery against a handful of implementations cannot support one, and a
  single number would be read as though it could. What the methodology produces
  is category-level observation with the denominator stated.

## The public evidence viewer

The [viewer](../viewer/) renders one JSON document offline. The dataset that
ships with this distribution is **synthetic**: generated by
`mcp-failure-lab viewer fixture`, describing invented implementations and
invented measurements, authored to demonstrate the document. It is not
anonymised private evidence, and the exporter refuses to write a public-safe
document that still carries a private execution's name.

```bash
uv run mcp-failure-lab viewer fixture --out artifacts/viewer-fixture
uv run mcp-failure-lab viewer export \
  --benchmark artifacts/viewer-fixture --mode public-safe --out viewer/public/data
```
