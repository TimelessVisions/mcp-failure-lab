# demos

Two three-minute walkthroughs of the evidence viewer, at the two visibilities.

|  | `private/` | `public-safe/` |
|---|---|---|
| Records | the private viewer, built from a real Benchmark 0.3 artifact | the public-safe viewer, built from the synthetic fixture |
| Shows | real measurements of real third-party implementations | invented implementations and invented numbers |
| Audience | owner-authorized technical review only | public, after the privacy review in its runbook |
| Recording committed | **no** — git-ignored, produced locally, deleted afterwards | yes |
| Runtime | 3:10 | 3:08 |

The public-safe demo is not the private one with the names removed. It has a
different subject: the private demo shows findings, the public-safe demo shows
how a finding would be established and what stops it being overstated. Nothing
in it is an anonymised version of a real result.

## What is in each directory

- `timeline.json` — the stage sequence and the dwell on each. This drives the
  capture *and* generates the captions, which is the only arrangement in which
  the two cannot drift apart.
- `script.md` — what a presenter says, with the beats timed, and a closing list
  of things that must not be said.
- `storyboard.md` — the shot list, what is held and why, and what is
  deliberately out of frame.
- `runbook.md` — how to build the viewer, record it, verify it, and (for the
  public-safe demo) the privacy review before any public use.
- `captions.vtt` — generated by the capture from `timeline.json`.
- `recording/` — two 1920×1080 WebM masters, standard and reduced-motion.

## Producing them

```bash
# public-safe
node demos/capture.mjs --mode public-safe --dist viewer/dist --out demos/public-safe
node demos/verify.mjs demos/public-safe

# private — see demos/private/runbook.md first
node demos/capture.mjs --mode private --dist /tmp/private-viewer --out demos/private
node demos/verify.mjs demos/private
```

`capture.mjs` refuses a build whose dataset does not match the mode asked for,
asserts every stage id against the timeline, aborts anything that leaves the
page's own origin, and trims each master to the timeline's planned length.
`verify.mjs` decodes the results in a browser and fails a master that is not
1920×1080 or that falls outside 2:45–3:15.

Both use the Playwright and ffmpeg that `viewer/` already pins. There is no
`package.json` here, deliberately: a second lockfile would be a second version
of the browser this repository records with.

## Determinism

Same build in, same route and focus sequence out. The fixture is generated
deterministically, the walkthrough advances only by `ArrowRight`, the dwell
times are committed, and the page reaches no network. The encoder's bytes are
not reproducible; the content is.

A capture that fails with a stage-id mismatch means the walkthrough changed.
Fix the timeline and the script together — that failure is the mechanism
working, not an obstacle to route around.
